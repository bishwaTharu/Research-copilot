# ADR-4: Local Embeddings for Index Stability

## Status
Accepted

## Context
Free LLM gateways (such as FreeLLMAPI) dynamically cycle upstream providers when rate limits or server errors occur. Upstream providers offer distinct embedding spaces (e.g., OpenAI `text-embedding-3`, Google `text-embedding-004`, Voyage, Cohere) that are mathematically incompatible. If embeddings are generated by different models across runs or chunks, vector similarity search fails completely.

## Decision
All dense vector embeddings for text chunks, figure captions, and user queries shall be computed using a single, pinned local embedding model (e.g. `sentence-transformers/all-MiniLM-L6-v2` or `BAAI/bge-small-en-v1.5`):
1. The embedding model identifier and dimension (e.g., `all-MiniLM-L6-v2`, 384 dimensions) are permanently recorded alongside every vector record in the database (`INT-05`).
2. Switching the embedding model requires an explicit database migration and complete re-indexing.
3. Generating embeddings does not consume FreeLLMAPI rate limits or fail during gateway downtime.

## Consequences
- **Pros**: Complete index stability, zero reliance on external quota for retrieval, fast query latency, offline functionality.
- **Cons**: Requires local compute (CPU/CUDA) and local model weights.
